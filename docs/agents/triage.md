# Triage

Rules for `/triage` and any session that files or triages tickets. Label strings live in `docs/agents/triage-labels.md`. Creating an issue and moving its project Status live in `docs/agents/issue-tracker.md`.

The board is the user project "Jhony.dev Project". **Backlog** is intake. **Ready** is the column a ticket may enter only after the gates below.

Every comment posted during triage starts with:

```
> *This was generated by AI during triage.*
```

## Empty body

On every triage session, before other triage work, list open issues:

```bash
gh issue list --state open --limit 100 --json number,title,body,labels
```

A ticket has no body when `body` is empty or only whitespace. For each one:

- Add `needs-info`.
- Remove the other state roles that are present: `needs-triage`, `ready-for-agent`, `ready-for-human`, `wontfix`.
- Leave `in-progress` in place, and mention it in the session report.
- If its project Status is Ready, set Status to Backlog (see [Ready column](#ready-column)).

`needs-info` is the label for a missing body. The tracker does not use a `need-info` label.

Comment on the issue that the body is empty and what is needed to fill it in.

## Making a ticket ready

Do this before applying `ready-for-agent` or `ready-for-human`, and before setting project Status to Ready. A request such as "move #42 to ready-for-agent" still stops at these two questions. Wait for an answer each time.

1. Show the maintainer the current body and ask them to validate it.
2. Draft an agent brief using `.agents/skills/triage/AGENT-BRIEF.md` and ask them to agree to that text.

After both answers are yes:

- Post the agreed brief as a comment. The comment contains an `## Agent Brief` heading.
- Apply exactly one of `ready-for-agent` or `ready-for-human`, and remove the other state roles.
- Set project Status to Ready, using the Status mutation in `docs/agents/issue-tracker.md` with the option named `Ready`.

`ready-for-human` uses the same brief and states why a person has to do the work.

## Ready column

On every triage session, list board items and keep those whose Status is `Ready`:

```bash
GH_TOKEN="$GH_PROJECT_TOKEN" gh api graphql -f query='
  query {
    user(login: "Jhony0311") {
      projectV2(number: 2) {
        items(first: 100) {
          nodes {
            id
            content {
              ... on Issue { number title state }
            }
            fieldValueByName(name: "Status") {
              ... on ProjectV2ItemFieldSingleSelectValue { name }
            }
          }
        }
      }
    }
  }'
```

For each open Ready issue, read body, labels, and comments with `gh issue view <number> --comments`. It stays in Ready only when all three hold:

- Exactly one ready label, `ready-for-agent` or `ready-for-human`, and no other state role.
- A comment that contains an `## Agent Brief` heading.
- A non-empty body.

When any check fails, highlight the issue in the session report with the number, title, and which checks failed. Then send it back:

- Set project Status to `Backlog`.
- If the body is empty, apply the [empty body](#empty-body) label update (`needs-info`).
- Otherwise add `needs-triage` and remove `ready-for-agent`, `ready-for-human`, and any other state role that is present.
- Leave `in-progress` in place, and mention it in the highlight.

Do this during the session, then show the maintainer the list of tickets that moved.

## What needs attention

After the empty-body pass and the Ready-column audit, present the usual buckets, oldest first: unlabeled issues, `needs-triage`, and `needs-info` whose reporter has replied since the last triage notes. Lead the report with what the two passes just changed.
