# DESIGN.md owns visual decisions

`DESIGN.md` is the source of truth for visual language, tokens, and accessibility. Coding guidelines cover component boundaries, naming, when to extract, and Astro versus React, and they link to `DESIGN.md` instead of restating it. A deterministic check validates the file's structure. The required sections are the six headings the doc has now: visual theme, color palette, typography, component stylings, layout, and implementation rules. That check belongs with the design-guideline work, not with the first lint slice. Whether a diff follows the prose is a Bugbot rule. Narrow mechanical bans, such as arbitrary color utilities, are deterministic rules and do not parse the markdown. Update `DESIGN.md` in the same change when the design system changes: a new token, or a new value for a token the doc already defines, such as the type scale. Bringing code into line with tokens the doc already names does not require a doc edit. A one-off arbitrary value the doc does not claim to specify does not require one either. Issue #5 originally asked the coding guidelines to cover tokens and accessibility too. Keeping both copies would let the two documents drift.
